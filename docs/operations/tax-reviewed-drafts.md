# Tax draft review and retention

Tax input drafts are separate from immutable shared templates, effective configurations, calculated workpapers, canonical selections and external filing. The existing tax mapping, configuration and preparation permissions govern each draft kind. Tax canonical-management permission governs workpaper review, lock and cleanup. No role or connection grant is added.

Save draft stores a complete validated input revision without creating a mapping, activating a configuration or calculating a workpaper. Review changes records the exact entity/ledger/template, effective dates or period, prior mapping/configuration, proposed fields, selected account identities and readiness warnings. Review records the actor and time. Every edit clears approval. Lock version compares the reviewed hash against current dependencies and commits the frozen artifact in the same transaction as its lock revision. Retries use an idempotency key; stale revisions and simultaneous edits cannot silently overwrite one another.

Locked inputs cannot be edited or discarded. Create corrected version retains the original and starts a linked draft. A corrected prepared workpaper creates another immutable calculation in history with `correctionOfFilingId`; it does not automatically replace a canonical workpaper or change the original lifecycle. Selecting a canonical workpaper or archiving/superseding history remains a separate authorized operation. Mapping locks do not activate filing configurations, and no review or lock submits tax returns, posts journals, pays taxes or closes accounting periods.

Filing history exposes an exact-record retention preview with UUID, source reference, scope, frozen versions, review/lock/export events and dependencies. Delete draft requires the current preview hash/version and the literal confirmation `DELETE <uuid> UNFILED`. It hides only an eligible unfiled, unreviewed, unlocked, unreferenced PREPARED workpaper. Restore draft requires `RESTORE <uuid>` and restores the same UUID and unchanged snapshot. Deleted drafts have a dedicated view. There is no permanent-deletion operation.

Historical imports, source evidence, refreshed/corrected comparison lineage, asset adjustments, canonical decisions, reviews, locks and exports require retention. Prepared calculations can contain calculated reported-values; this is distinct from supplied reported evidence, whose provenance is stored separately. Legacy workpapers without creation-time control history are conservatively retained because prior exports or external use cannot be proven absent. Use reviewed archive/supersede for retained history. No existing tenant workpaper is automatically hidden, locked or relabeled by the migration.

All workpaper references and retention changes share a tenant governance fence. Database triggers also reject references to hidden records and enforce append-only audit history. Export retains an audit dependency before returning the file, so export/delete races cannot return an export of a newly hidden draft. The approved synthetic-demo reset registry includes both new event tables; private organizations are unaffected.
