# Agent booking reviews and outcomes

Use `finlynq_daily_create_booking_batch` to select exact source documents and manual journals in one company and ledger. Supply current source versions/content hashes or manual journal approval versions/content hashes. The returned immutable review link contains no posting authority. Include reviewer notes, held/deferred items and declared clearing-account groups when these explain financing, prepaid usage or unmatched evidence.

After ordinary authorization, `finlynq_daily_post_booking_batch` issues the selected draft bills/invoices and posts eligible manual journals through their existing commands. It does not submit or approve journals, alter tax-review requirements, or bypass connection tool restrictions. Settlements are booked through the existing settlement commands and can be included as already-posted sources. Each source is independently committed; held entries remain explicit when some postings succeed. Return the report URL to the user when booking completes.

The posting command automatically appends an outcome using actual posted journal lines and current source balances. Its original review remains available. Use `finlynq_daily_refresh_booking_batch_report` after booking through individual tools, after subsequent settlements, or when report generation failed. Refresh creates a new snapshot and performs no accounting mutation. Retry a command with identical arguments and idempotency key to recover its original result. A changed draft requires a newly selected review. Missing journal approval remains a normal posting blocker.

Reports are available under Reports → Booking reports, AI & MCP connections, and links in journal/source details. Exact historical links carry `reportId`; the batch URL without that query opens its latest snapshot. Read access requires active ledger permission plus the selected source modules. Original evidence downloads retain their exact source-version authorization. Definitions and snapshots are encrypted using organization keys; append-only records and business audit events preserve creator, request, command hash and review/outcome lineage.

Original-currency invoice totals are separate from functional-currency recognition and amounts still owed. Draft lines use the existing posting calculation and remain labelled draft. Tax details include recoverable/nonrecoverable components and explicit source rounding. Clearing checks cover only the selected records assigned to each declared group. Unmatched groups and held items prevent a report from being labelled complete. CSV exports neutralize spreadsheet formulas in untrusted text; printable HTML escapes descriptions and hides application navigation.

Validation covers committed PostgreSQL behavior, tenant and permission restrictions, immutable history, stale content, exact retry, partial results, report-outage recovery, signed multicurrency bills, source rounding/tax, shareholder/corporate-card settlements, clearing calculations, and accessible narrow-screen/print rendering with explicit synthetic fixtures.
