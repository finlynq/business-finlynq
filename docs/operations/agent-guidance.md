# Agent guidance files

The MCP server's startup instruction asks an agent to call `finlynq_guidance_get_index` after checking connection capabilities. That read returns the standard and organization `index.md` files with their references; other Markdown bodies are fetched one at a time with `finlynq_guidance_read_file`. `finlynq_guidance_list_files` lists all current paths if an index is missing or incomplete. Guidance is a persistent reference library, not an authorization source. A file may reference another as `platform:accounting/workflow.md` or `client:tax/notes.md`.

Organization files are visible as plain Markdown at `/app/settings/guidance` and through its authenticated raw-file link. The agent may create and update them with `finlynq_guidance_save_client_file`, using `expectedVersion: 0` for a new path or the current version for a revision. It can retire an obsolete file with `finlynq_guidance_retire_client_file`. A save does not silently rewrite `index.md`; the agent should maintain references as a separate versioned edit. Files and history are scoped to the current organization. An owner or administrator with `organization.settings.manage`, Daily write scope, and Daily mode `ALLOW_WRITES` can let the agent update files without per-edit confirmation. `CONFIRM_WRITES` continues to require the connection's normal per-action approval.

Each file is capped at 3,000 estimated tokens and 12,000 UTF-8 bytes. `index.md` is capped at 600 estimated tokens. The estimate is model-independent, so agents should split files before reaching the limit. At most 100 paths may be created per scope. Paths are lowercase relative `.md` names and cannot traverse directories. Every revision is append-only; retiring adds a new revision and removes the file from current indexes without erasing history. Expected-version checks serialize concurrent edits.

Finlynq-standard files live in `platform_guidance_files` and are readable by all authorized organizations. The seed contains a short index and a workflow file. `/app/platform/guidance` is visible to platform administrators; saving a new standard revision requires fresh MFA. The database function repeats the platform-role and step-up checks inside the write transaction. Tenant MCP tools never write standard files.

Guidance text may contain business facts, tax notes, and user preferences, but neither shared nor client guidance grants a permission or overrides a direct user instruction, tool contract, review rule, or source document. Do not put credentials or tokens in a plain file. Client facts should include effective dates and source references when those matter.
